# Локализация

Здесь лежит карта русской локализации форка и скрипт её применения.

```
mapping.json   пары «китайская строка → русская» для client.js, index.js, lib/olk.ps1
apply-ru.ps1   скрипт применения (PowerShell 5.1+)
```

## Зачем

Репозиторий уже содержит переведённые файлы — скрипт нужен, если вы обновляете форк до
новой версии upstream: берёте новый `index.js`/`client.js`/`lib/olk.ps1` из
[UnknowCao/dsh-outlook](https://github.com/UnknowCao/dsh-outlook) и заново применяете
перевод, не разыскивая строки вручную.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\localization\apply-ru.ps1
```

## Поведение

- идемпотентно: уже переведённые строки пропускаются;
- если исходная строка не найдена (upstream её изменил) — скрипт завершается с кодом 2
  и **ничего не записывает**, чтобы не испортить файлы; тогда поправьте `mapping.json`;
- учитывает разные окончания строк: JS в репозитории с LF, `.ps1` — с CRLF;
- `.ps1` записывается с BOM (иначе Windows PowerShell 5.1 ломает кириллицу).

## Что не переводится скриптом

- описания параметров инструментов (`description` в `index.js`) — служебный текст для
  модели, оставлен на английском;
- `CHANGELOG.md`, `TESTCASES.md`, `README.zh.md` — материалы автора оригинала;
- в двух регулярных выражениях (`lib/olk.ps1`: поиск GAL и списка переговорных)
  китайские варианты имён оставлены рядом с английскими и русскими — это данные для
  совместимости, в интерфейсе они не видны.

## Изменения, которые не являются переводом

Помимо строк, в `lib/olk.ps1` исправлены три вещи, из-за которых плагин плохо работал в
локализованном Outlook (в `mapping.json` они тоже есть):

1. **GAL**: добавлено имя `Глобальный список адресов` и резервный выбор адресного списка
   с наибольшим числом записей — иначе `outlook_search_people` возвращал 0 результатов;
2. **Папки**: `Входящие`, `Отправленные`, `Черновики` понимаются как имена по умолчанию;
3. **Переговорные**: поиск по `Комнаты`/`Переговорные` + диагностический список имён
   адресных списков в тексте ошибки.
