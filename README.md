# dsh-outlook (русская локализация)

> **На рабочем компьютере, где IT не даёт прав на Graph API, ИИ напрямую работает с вашим Outlook.**
> Без учётных данных · без прав администратора · любая отправка — только после вашего подтверждения.

[![DSH Plugin](https://img.shields.io/badge/DSH-Plugin-blue)](https://www.npmjs.com/package/@deepseek-ai/dsh) [![Platform](https://img.shields.io/badge/Platform-Windows%20%2B%20classic%20Outlook-0078D4)](https://support.microsoft.com/en-us/office) [![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](./LICENSE) [![Tools](https://img.shields.io/badge/tools-18-8A2BE2)](#что-плагин-даёт)

**Неофициальный русский форк плагина [dsh-outlook](https://github.com/UnknowCao/dsh-outlook)** (автор — UnknowCao, MIT). Взята версия v2.11.0; добавлены русский интерфейс и исправления для локализованного Outlook. Оригинальная документация автора сохранена в [README.zh.md](./README.zh.md).

*Автоматизация Outlook без учётных данных для ИИ-агентов на Windows: плагин управляет локальным классическим Outlook через COM. Не нужны регистрация приложения в Azure, пароль SMTP или права администратора тенанта — всё, что покидает машину, проходит трёхуровневое подтверждение человеком.*

## Что изменено относительно оригинала

| Изменение | Зачем |
|---|---|
| Русские строки интерфейса (боковая панель, всплывающий список, тосты) | панель плагина была только на китайском |
| Русские тексты подтверждений перед отправкой письма и приглашения | вы видите состав отправления по-русски: «Кому / Копия / Скрытая копия / Тема / Текст письма» |
| Русские подписи карточек инструментов | в чате видно, что именно делает плагин |
| Поиск GAL: имя списка `Глобальный список адресов` + резервный выбор самого большого списка | в русском Outlook адресная книга не находилась, поиск людей отдавал 0 результатов |
| Русские имена папок: `Входящие`, `Отправленные`, `Черновики` | поиск по папкам работал только по английским/китайским названиям |
| Поиск переговорных: `Комнаты`/`Переговорные` + диагностика со списком адресных списков | на русской локализации список комнат не определялся |
| Русская цитата исходного письма: `----- Исходное сообщение -----`, `От:`, `Дата:`, `Кому:`, `Тема:` | ответы и пересылки оформлены по-русски |
| Русские сообщения об ошибках (папка/вложение не найдены) | понятнее при сбоях |

Всё остальное — код, логика, трёхуровневая защита отправки — без изменений. Исправления GAL, папок и переговорных актуальны и для других локализаций, но проверены на русской версии Outlook 2016 + Exchange.

## Когда он нужен

1. **На корпоративном компьютере стоит классический Outlook, а IT не разрешает регистрировать приложения Azure** — все решения на Graph API (outlook-mcp и аналоги) упираются в app registration, а этому плагину она не нужна: он управляет уже авторизованным настольным клиентом.
2. **Хочется, чтобы ИИ был почтовым секретарём**: утром спросить «что нового в почте» — он прочитает; сказать «ответь на это письмо, что в среду смогу» — он подготовит ответ с цитатой и отправит только после подтверждения в диалоге.
3. **Нужно назначить встречу, но неизвестно, кто свободен**: одной фразой проверить занятость коллег и свободные переговорные; приглашение уйдёт только после вашего подтверждения.

## Что плагин даёт

**18 инструментов** (чтение выполняется сразу; любое действие наружу требует подтверждения в диалоге):

| Инструмент | Назначение | Контроль |
|---|---|---|
| `outlook_check_new` | Новые письма (синхронизация со счётчиком в боковой панели) | только чтение |
| `outlook_search_mail` | Поиск писем (период / папка / отправитель / тема / даты / получатель), со ссылками «Открыть» | только чтение |
| `outlook_read_mail` | Полный текст письма (тело, получатели, вложения; длинное обрезается) | только чтение |
| `outlook_open_mail` | Открыть письмо в отдельном окне Outlook (помечает прочитанным) | локальное действие |
| `outlook_account` | Текущая учётная запись и SMTP-адрес | только чтение |
| `outlook_draft_mail` | Создание черновика (**никогда не отправляет**, можно с вложениями) | безопасно |
| `outlook_send_mail` | Отправка письма | тройное подтверждение |
| `outlook_reply_mail` | Ответ / ответ всем / пересылка (автоцитата, вложения оригинала) | тройное подтверждение |
| `outlook_calendar_query` | Календарь на N дней вперёд (с повторяющимися встречами) | только чтение |
| `outlook_calendar_create` | Личная запись создаётся сразу; с участниками — приглашение (в т.ч. повторяющееся) | приглашение — с подтверждением |
| `outlook_meeting_requests` | Приглашения на встречи, ждущие ответа | только чтение |
| `outlook_respond_meeting` | Принять / принять с оговоркой / отклонить приглашение | подтверждение (уведомляет организатора) |
| `outlook_meeting_update` | Изменение встречи или записи (участники уведомляются) | подтверждение |
| `outlook_meeting_cancel` | Отмена встречи (уведомление участникам) или удаление личной записи | подтверждение |
| `outlook_search_people` | Поиск в адресной книге (GAL) по имени / e-mail / псевдониму | только чтение |
| `outlook_freebusy` | Занятость коллег с шагом 30 минут | только чтение |
| `outlook_search_rooms` | Поиск переговорных + проверка свободного времени | только чтение |
| `outlook_save_attachment` | Сохранение вложения на диск (без выхода за каталог и без перезаписи) | локальная запись |

**Плюс счётчик в боковой панели**: при новом письме у кнопки Outlook появляется красный индикатор, по клику — список последних поступлений; **клик по письму открывает его в Outlook** (помечает прочитанным, счётчик уменьшается). Такие же ссылки `[Открыть]` работают в чате: плагин перехватывает клик на странице и открывает письмо без новой вкладки.

## Быстрый старт

```sh
# из GitHub (этот форк)
dsh plugin --profile web add https://github.com/vital1972/dsh-outlook-ru

# или оригинал из npm
dsh plugin --profile web add dsh-outlook
```

Затем перезапустите профиль (или полагайтесь на `patchReload: live`). Больше ничего делать не нужно: никаких учётных данных, регистрации приложений и изменения настроек Outlook.

**Требования**: Windows + классический настольный Outlook (`OUTLOOK.EXE`) с выполненным входом + Windows PowerShell 5.1 (входит в систему). Права администратора тенанта не нужны.

## Чем отличается от аналогов

| | dsh-outlook | Решения на Graph API (outlook-mcp и др.) | Решения на SMTP (mcp-server-email) |
|---|---|---|---|
| Регистрация приложения в Azure | ❌ не нужна | ✅ обязательна (в компаниях обычно закрыта IT) | ❌ |
| Пароль или учётные данные почты | ❌ | OAuth-токен | ✅ пароль SMTP |
| Видит состояние «живого» клиента (непрочитанные, правила, локальные папки) | ✅ | частично | ❌ |
| Подтверждение перед отправкой | тройной контроль (ниже) | зависит от реализации | зависит от реализации |
| Платформа | только Windows, классический Outlook | любая | любая |

## Границы безопасности

**Любое действие, покидающее машину — отправка письма или приглашения, — проходит три независимых проверки:**

1. **Протокол двух подтверждений**: первый вызов только возвращает состав будущего отправления; ИИ обязан показать его вам дословно, и лишь после явного разрешения повторный вызов с `confirmed:true` выполняется;
2. **Привязка к хешу содержимого**: показанное при подтверждении содержимое сравнивается по SHA-256 с отправляемым — подмена «показали A, отправили B» отсекается на уровне хоста и принудительно возвращается на повторное подтверждение;
3. **Токен моста**: PowerShell-мост независимо отклоняет любые пути отправки без одноразового токена `OLK_CONFIRM` — даже если будущая ошибка или новый инструмент обойдёт первые два уровня, без токена письмо не уйдёт.

**Чего плагин не делает**: никогда не отправляет что-либо молча; не сохраняет и не передаёт учётные данные почты (он их не касается); черновики никогда не отправляются автоматически; при сохранении вложений отклоняет выход за пределы каталога и перезапись существующих файлов.

Известные ограничения: служебные маршруты `/olk-notify/*` доступны только с этой машины и проверяют источник (но другие локальные процессы технически могут прочитать темы новых писем); ссылки «открыть» в чате работают по POST-маршруту `/olk-notify/open` (клик со средней кнопкой/модификатором вернёт 405 — так задумано, инструмент `outlook_open_mail` работает всегда); несколько вкладок используют одну очередь непрочитанного; приход писем можно отключить переменной `OLK_WATCH=0`.

## Структура файлов

```
index.js          серверная часть: 18 инструментов, двойное подтверждение, хеш содержимого, watcher, маршруты
client.js         браузерная часть: кнопка в слот sidebar.footer.action, счётчик, всплывающий список (React Portal)
lib/olk.ps1       COM-мост: все операции Outlook + токен-контроль + особенности локализованного клиента
lib/watch.ps1     постоянный слушатель NewMailEx: уведомления о новых письмах, самовосстановление через 30 с
cordis.patch.yml  объявление серверной строки
localization/     карта русской локализации и скрипт применения (для будущих обновлений upstream)
TESTCASES.md      49 тест-кейсов (на языке автора)
CHANGELOG.md      история версий (на языке автора)
README.zh.md      исходная документация автора
```

Диагностический лог: `%TEMP%\dsh-outlook-watch-debug.log` (ротация на 1 МБ).

## Проверка и тесты

- 49 кейсов покрывают всю цепочку ([TESTCASES.md](./TESTCASES.md)); автоматические проверки пройдены на реальном Exchange: приход письма → счётчик → очистка, принудительное завершение watcher с восстановлением через 30 с, блокировка двух видов подмены при подтверждении, ответы маршрутов 405/413, ротация логов, «открыть = прочитано», регрессия кодовой страницы, перехват ссылок в чате;
- Особенности COM (двухступенчатая фильтрация Jet/DASL, формат даты в Restrict, счётчик MaxInt у IncludeRecurrences, кодировка stdin в PS 5.1) учтены в `lib/olk.ps1` и проверены на реальном Exchange.

## Поддержание перевода

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\localization\apply-ru.ps1
```

Скрипт идемпотентен: переводит только найденные исходные строки, если строка уже переведена — пропускает, если не найдена — завершается с ошибкой, ничего не записав (защита от порчи файлов после обновления upstream).
